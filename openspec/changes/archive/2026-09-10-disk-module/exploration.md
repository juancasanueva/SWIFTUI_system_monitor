## API facts verified in SDK headers

IOKit (`/Applications/Xcode.app/Contents/Developer/Platforms/MacOSX.platform/Developer/SDKs/MacOSX.sdk/System/Library/Frameworks/IOKit.framework/Versions/A/Headers/`):

- `storage/IOBlockStorageDriver.h`: `#define kIOBlockStorageDriverClass "IOBlockStorageDriver"` (41); `#define kIOBlockStorageDriverStatisticsKey "Statistics"` (54); `#define kIOBlockStorageDriverStatisticsBytesReadKey "Bytes (Read)"` (68), discussion 62-65 "number of bytes read since the block storage driver was instantiated ... It has an OSNumber value"; `#define kIOBlockStorageDriverStatisticsBytesWrittenKey "Bytes (Write)"` (82). Sibling keys exist for operations, latency, total time, errors, retries (96-222) and are not needed.
- Swift import: these are plain string-literal `#define`s, but the header belongs to the explicit submodule `IOKit.storage` (`Modules/module.modulemap:171-186`, header listed at 186). A plain `import IOKit` does not load explicit submodules, so the constants are invisible to the code that exists today; `import IOKit.storage` would be required and, if that submodule imports cleanly into Swift, they surface as `String` constants. Not compile-verified in this session (no compiler access). Zero-risk route: spell `"IOBlockStorageDriver"`, `"Statistics"`, `"Bytes (Read)"`, `"Bytes (Write)"` as private `static let`s citing the header lines, exactly as `IORegistryCoreTopologyProvider.swift:17-23` does for `"AppleARMPE"`/`"cluster-type"`. The adapter's first RED compile settles whether the submodule import is preferable.
- `IOKitLib.h`: `extern const mach_port_t kIOMainPortDefault __API_AVAILABLE(macos(12.0), ...)` (111-113); `kIOMasterPortDefault` is `__API_DEPRECATED_WITH_REPLACEMENT("kIOMainPortDefault", macos(10.0, 12.0))` (132-135). Deployment target 26.5 and the existing adapter already use `kIOMainPortDefault`. `IOServiceGetMatchingServices(mach_port_t mainPort, CFDictionaryRef matching CF_RELEASES_ARGUMENT, io_iterator_t *existing)` (442-446): the matching dictionary is consumed (never `CFRelease` it, 438), the iterator must be released by the caller, and a NULL iterator with success means no match (439). `IOIteratorNext` (391-393), `IOObjectRelease` (266-268). `IORegistryEntryCreateCFProperty(entry, CFStringRef key, CFAllocatorRef, IOOptionBits) -> CFTypeRef` created for the caller (1186-1191) — in Swift `?.takeRetainedValue()` as the topology adapter does.
- Value types: `Statistics` arrives as `CFDictionary` (bridge to `[String: Any]`), each counter as `CFNumber`/`NSNumber` from an `OSNumber`; extract with `(dictionary["Bytes (Read)"] as? NSNumber)?.uint64Value`. `iostat` reads the same numbers with `CFNumberGetValue(number, kCFNumberSInt64Type, &value)` into `u_int64_t`.
- Swift call shape for the adapter:
  ```swift
  guard let matching = IOServiceMatching("IOBlockStorageDriver") else { throw ReadError.matchingUnavailable }
  var iterator: io_iterator_t = IO_OBJECT_NULL
  let status = IOServiceGetMatchingServices(kIOMainPortDefault, matching, &iterator) // consumes `matching`
  guard status == KERN_SUCCESS else { throw ReadError.ioKitCall(status) }
  defer { IOObjectRelease(iterator) }
  while case let driver = IOIteratorNext(iterator), driver != IO_OBJECT_NULL {
      defer { IOObjectRelease(driver) }
      guard let statistics = IORegistryEntryCreateCFProperty(driver, "Statistics" as CFString, kCFAllocatorDefault, 0)?
          .takeRetainedValue() as? [String: Any] else { continue }
      read &+= (statistics["Bytes (Read)"] as? NSNumber)?.uint64Value ?? 0   // or saturating add
      written &+= (statistics["Bytes (Write)"] as? NSNumber)?.uint64Value ?? 0
      driverCount += 1
  }
  ```
- `iostat` (`apple-oss-distributions/system_cmds`, directory `iostat/iostat.c`, main branch): matches `IOServiceMatching("IOMedia")` with `kIOMediaWholeKey` = true, walks `IORegistryEntryGetParentEntry(drive, kIOServicePlane, &parent)` and keeps parents where `IOObjectConformsTo(parent, "IOBlockStorageDriver")`, reads `IORegistryEntryCreateCFProperties` then `CFDictionaryGetValue(properties, CFSTR(kIOBlockStorageDriverStatisticsKey))` and the two byte keys, extracts with `kCFNumberSInt64Type`, measures elapsed time with `timersub` on wall-clock `timeval`s and divides the byte delta by it, and releases with `CFRelease(properties)`, `IOObjectRelease(parent)`, `IOObjectRelease(drive)`. `kIOMediaClass "IOMedia"` (`storage/IOMedia.h:41`), `kIOMediaWholeKey "Whole"` (168). PRD R10.3 iterates the drivers directly, which yields the same counters without the parent walk; the two sets differ only for a driver with no published whole media (not expected on a running Mac).

Capacity (Foundation):

- `Foundation.framework/Headers/NSURL.h`: `NSURLVolumeTotalCapacityKey` macos(10.6) "Total volume capacity in bytes (Read-only, value type NSNumber)" (315); `NSURLVolumeAvailableCapacityKey` macos(10.6) "Total free space in bytes" (316); `NSURLVolumeAvailableCapacityForImportantUsageKey` macos(10.13) (361) documented at 355-359: "Total available capacity in bytes for "Important" resources, including space expected to be cleared by purging non-essential and cached resources. "Important" means something that the user or application clearly expects to be present on the local system, but is ultimately replaceable ... This value should not be used in determining if there is room for an irreplaceable resource." `...ForOpportunisticUsageKey` (363-367) also includes purgeable space.
- Swift overlay (`Foundation.swiftmodule/arm64e-apple-macos.swiftinterface`): `volumeTotalCapacity: Int?` (16007), `volumeAvailableCapacity: Int?` (16010), `volumeAvailableCapacityForImportantUsage: Int64?` (16016), `volumeAvailableCapacityForOpportunisticUsage: Int64?` (16022). Read with `try URL(fileURLWithPath: "/").resourceValues(forKeys: [.volumeTotalCapacityKey, .volumeAvailableCapacityForImportantUsageKey])`; the call throws and each value is optional, so the adapter needs a typed error for "key missing" (R10.9 Unavailable). Convert `Int`/`Int64` to `UInt64` with a `>= 0` guard.
- Finder alignment is asserted by PRD 4.5/R10.2 and consistent with the header ("including space expected to be cleared by purging"); it was not numerically verified here (manual success-metric check, PRD section 2). `statfs`/`volumeAvailableCapacity` exclude purgeable space and would under-report Free versus Finder.
- Cost: Apple documents no figure; the 10 s cadence (R10.7) makes it moot for the CPU budget.
- Units: `NSByteCountFormatter.h:27-34` — `File`: "on OS X 10.8, this uses the decimal style, but that may change over time"; `Memory`: binary "may change"; `Decimal`: 1000; `Binary`: 1024. swift-foundation `ByteCountFormatStyle.swift` (FoundationInternationalization) implements `switch style { case .file, .decimal: decimal = true ... case .memory, .binary: decimal = false }`, so `.file` is decimal today and `.decimal` pins the same output without the header caveat. `FormatInput` is `Int64` (clamp `UInt64` as `ByteFormatter.swift:18` does).
- Throughput string (R10.5 `27,1 MB/s`, one fraction digit): `ByteCountFormatStyle` chooses its own fraction digits per unit and offers no `/s` suffix, so a small pure formatter is needed: pick the decimal unit (B, kB, MB, GB, TB) by 1000-steps, format the number with `.number.precision(.fractionLength(1)).locale(locale)`, append the unit and `/s`. `Measurement<UnitInformationStorage>` + `.measurement(width: .abbreviated, usage: .asProvided, numberFormatStyle: ...)` is an alternative for locale-aware unit symbols, but no per-second information-storage unit exists, so `/s` is appended either way. Unit vocabulary (`kB` vs `KB`) is a design choice to pin under `en_US`/`de_DE`.

## Sampling cadence for capacity (R10.7) and elapsed time (R10.3)

- Time source constraint: the sampler's clock is the existential `any Clock<Duration>` (`MetricsSampler.swift:69,84`) and tests inject `ManualClock`. The existential erases `Instant`, so `clock.now` cannot produce a storable, comparable instant without opening the existential in a generic context (SE-0352) and restructuring `start()`. Three options:
  - T1 (recommended, matches PRD 6.2 `timestamp: ContinuousClock.Instant`): the throughput adapter stamps every read with `ContinuousClock.now`; the Domain rate is `Δbytes / Δt` from consecutive stamps, and the capacity cadence compares the stamp with the instant of the last capacity read (`shouldRefresh(lastReadAt:now:minimum: .seconds(10))`). One time source drives both rules; fakes script instants with `ContinuousClock.now.advanced(by:)` (only differences matter, so tests stay deterministic and never sleep). `ContinuousClock.Instant` is stdlib `Sendable, Hashable, Comparable`, so Domain values stay `Sendable, Equatable` and the "Foundation only" rule holds.
  - T2: tick counter (`ceil(10 s / interval)` ticks). Simplest, but the count depends on the interval and every `apply(interval:)` restart, and Δt for the rate would still be needed.
  - T3: make `MetricsSampler` generic over `Clock`. Correct but invasive for a verified loop; not worth it for one metric.
- Where: a `DiskSamplingStep` value (like `CPUSamplingStep`) holding `previous: DiskThroughputCounters?`, `capacity: VolumeCapacity?`, `capacityReadAt: ContinuousClock.Instant?`; `advanced()` returns `(snapshot: DiskSnapshot?, next: DiskSamplingStep)`. The loop keeps it in a `var` next to `step` (113-127) and `sampleOnce()` keeps an `inlineDiskStep` next to `inlineStep` (72, 188-195). `apply(interval:)` needs no change: the restart builds a fresh step, so the first tick of the new loop re-reads capacity and re-seeds the throughput baseline (one throughput-unavailable tick, the exact analogue of CM-2's publish-free CPU tick; the spec must state it).
- First tick after start (R10.3 last sentence): capacity present, rates nil → `apply(disk:)` publishes a snapshot with `readBytesPerSecond == nil`. Memory's "publishes on iteration one" precedent (MM-5) applies to capacity.
- Failure isolation (MM-7 analogue): a throughput throw publishes capacity with nil rates (R10.9 em dash); a capacity throw with no cached capacity publishes nothing (card shows Unavailable); a capacity throw after a success is an open question (keep last values vs. Unavailable).

## Recommendation

P1 + T1 + D1 + F1 + S1. Port with `readThroughput()`/`readCapacity()`, adapter-stamped instants, a pure `DiskThroughputCalculator` (negative delta → both rates nil, baseline re-seeded) and a pure cadence rule, a `DiskSamplingStep` value living in the loop and in `sampleOnce()` exactly like `CPUSamplingStep`, `apply(disk:)` storing only the latest snapshot, `DiskCard` + `DiskCardModel` mirroring `MemoryCardModel` (sections array, locale injection, `gaugeAnimation` delegating to `CPUCardModel`), a `ThroughputLabel` component, `Palette.diskAccent`, `ByteFormatter.capacity` on `.decimal` plus a one-fraction-digit throughput formatter with a `/s` suffix. Spell the four IOKit strings as literals with header citations unless the first compile proves `import IOKit.storage` exposes them. Give the disk fake default arguments in the four `makeSampler`-style helpers so the test target compiles in the first RED.

## Test plan sketch (strict TDD)

- Domain: `used = total − free` saturating, `fraction` 0 for `total == 0` and capped at 1; rate = Δ/Δt with reference numbers (27.1 MB/s from 27 100 000 bytes over 1 s); `previous == nil` → nil; negative read delta → both nil; negative write delta → both nil; `Δt <= 0` → nil; `driverCount == 0` → nil; cadence: refresh at 0 s, not at 9.999 s, at 10 s, and when `lastReadAt == nil`.
- Application: first `sampleOnce()` publishes disk with capacity and nil rates while CPU stays nil; second publishes rates; throughput throw keeps capacity and nils rates; capacity throw on tick one publishes nothing, on a later tick keeps the cached capacity (or Unavailable, per OQ5); capacity read count is 1 across ticks whose instants stay under 10 s and 2 once they cross it; all three providers' call counts advance together; `readOnMainThread` all false in the `ManualClock` loop; `apply(interval:)` restart re-reads capacity and nils rates for one tick; `apply(disk:)` touches no other state.
- Infrastructure `.integration`: the three shape tests above.
- Presentation: rows `[Used, Free, Total]` with `"432.07 GB"`/`"432,07 GB"`; gauge `"87.4%"`; `"27.1 MB/s"`/`"27,1 MB/s"`, `"2.2 MB/s"`, `"0.0 kB/s"` or `"0 B/s"` (design), em dash + "unavailable" label for nil rates; icons differ and both resolve; `sections == [.header, .gaugeAndRows, .throughput]`; reduce-motion animation nil; nil snapshot renders the full skeleton at the same height; `PanelView` height ≥ cpu + memory + disk + chrome and `diskAccent == memFree` value.

## Risks

- Sandbox: no document allows `iokit-get-properties` for App Sandbox apps; the evidence is the green sandboxed topology test on a different class. If `Statistics` turns out filtered, R10.9's unavailable footer is the fallback and the `.integration` test fails first (Infrastructure, not Domain).
- A required `diskProvider:` init parameter breaks compilation at four test sites (`MetricsSamplerTests.swift:25,314`, `SamplingCadenceTests.swift:98`, `SettingsStateTests.swift:296`); mitigate with a defaulted fake in the helpers in the same RED step.
- `import IOKit.storage` may not import cleanly into Swift 6 (C++-flavoured storage headers); literals avoid the dependency.
- Counter resets across ejects/mounts (R10.4) drop one tick of throughput; disk images (`hdiutil`) and Time Machine volumes inflate the sum relative to the boot disk only.
- `ContinuousClock.Instant` in the Domain cannot be constructed from a literal; fixtures derive from one `ContinuousClock.now` base (differences only).
- Locale strings from `.number`/`ByteCountFormatStyle` may carry U+00A0/U+202F; reuse the normaliser from `ByteFormatterTests.swift:16-20`.
- Popover height grows from 678 pt to roughly 850–870 pt (disk card estimate ≈ 176 pt: header + 84 pt gauge row + footer + 2×14 spacing + 32 padding); still fits a 14" display but the PanelViewTests comment must be refreshed and PRD 10 notes the growth.
- `volumeAvailableCapacityForImportantUsage` may differ from Finder on unusual volumes (external boot, Fusion); success metric is a manual check.
- SF Symbol names (`internaldrive`, `arrow.down.doc`/`arrow.up.doc` or `arrow.down.circle.fill`/`arrow.up.circle.fill`) were not machine-verified (glyph catalogue plists are binary, SF Symbols app not installed); pin with an `NSImage(systemSymbolName:)` test.
- Delivery is single-PR across five layers plus specs (`review_budget_lines: unlimited`), same shape as M3/M4.

## Open questions (surface only; the orchestrator owns the decisions)

1. Port shape: P1 (one port, two methods) vs P2 (two ports) vs P3 (PRD-literal single counters value) — P1 recommended.
2. Throughput set: every `IOBlockStorageDriver` (R10.1, includes disk images and external drives) vs `iostat`'s whole-`IOMedia` parents vs only the physical store behind `/`.
3. Capacity units: `.decimal` (pinned) vs `.file` (PRD wording); throughput unit vocabulary (`kB`/`MB`/`GB`, `B/s` below 1 kB) and the zero string.
4. Restart semantics: one throughput-unavailable tick after `apply(interval:)` (CPU precedent) vs carrying the baseline across restarts.
5. Capacity failure after a prior success: keep the last values or show Unavailable (R10.9 wording covers the throwing query, not the cached case).
6. Unavailable card state: distinct "Unavailable" text (R10.9) vs the nil-snapshot skeleton, and whether the skeleton must keep the populated height (memory-card "Nil snapshot" precedent).
7. Confirm the amber-to-green gradient stays P2 (R10.10) and that no menu bar module or settings entry is added (R10.11).
8. Whether PRD 6.2 should be amended to the two-value port (`DiskThroughputCounters` + `VolumeCapacity`) the way MM-10 amended R4.2.
